# Testing strategy

## Phase 02 validation

Unit (`pnpm test`): DOI/provider identity normalization, search/command/upload/anchor contracts, BibTeX/RIS escaping, keys and missing fields, provider adapters against synthetic documented-shape fixtures (`tests/fixtures/providers`, not recorded live), bounded HTTP retry/Retry-After/timeouts/cancellation/size limits, partial and total provider failure without fake results, DOI-only merging, request-bound cursors, reader anchor offsets/rectangles/recovery and the sign-in feedback regression.

Integration (`pnpm test:integration`, disposable PostgreSQL, non-owner runtime): concurrent DOI/provider saves, idempotent replay and payload conflict, cross-tenant reads (services and raw SQL), raw DML denial, viewer/editor/workspace-admin matrix, private sources outside global metadata, collections/tags/status/version conflicts, archive/restore, signed cursors, export, upload quarantine/mismatch/replay/expiry, scan leases/retry/checksum binding, READY-only access, immutability triggers, private/shared annotation ACLs, membership revocation and audit events. Storage is an explicit in-memory double here; real Storage runs in the browser harness.

Browser (`pnpm test:auth:e2e`): `tests/auth/compose.yml` now also starts the real Supabase Storage API (file backend) behind the loopback gateway, and Playwright starts `tests/auth/provider-fixture.mjs`. `research-library.spec.ts` registers a real account and covers search, details, saves, partial provider failure, collections/tags/status persistence across reload, private upload, quarantine denial, direct Storage denial with the user's own token, the scanner protocol (verdict supplied by the test and labelled as such), reader navigation/zoom/search/keyboard, highlights and notes persisted across reload with version/anchor checks, axe, BibTeX/RIS export and a second account's 404s for every research endpoint. Opt-in live provider smoke: see [provider adapters](research/PROVIDER_ADAPTERS.md).

## Phase 01 validation

`pnpm test:integration` uses `vitest.integration.config.ts`: real PostgreSQL migrations/runtime RLS/transactions and explicitly labeled mocked-SDK HTTP/session-boundary tests. It fails without explicit local disposable URLs; the database name must begin `atlas_p01_test`. Domain requests use a separate unprivileged login; admin credentials are fixture-only. Tests cover provisioning races, interrupted drafts/retries, idempotent project creation, visibility/role ceilings, parent constraints, invitation concurrency/replay/revoke/expiry/current inviter authority, last-owner races, version conflicts, archiving/recovery, parent revoke, reused-connection cleanup and distributed limits, late-transaction rollback, both organization/project owner races, and large-list signed cursor isolation.

`pnpm test:auth:e2e` runs real signup/email confirmation/login/logout/recovery and collaboration against disposable GoTrue plus Mailpit, using the approved live screens and real SQL. Start only the loopback `tests/auth/compose.yml` harness; apply migrations and grant `atlas_runtime` to its runtime login. Hosted Supabase is not used. The separate GitHub Actions job starts and destroys this harness. Auth traces/screenshots/video/mailbox artifacts are disabled to avoid token leakage. These tests do not prove hosted OAuth, SMTP or pooler operation.

The existing 101-test design suite stays in preview mode and retains screenshot, geometry, accessibility, interaction and no-fake-network assertions. A late manuscript mount now uses the same canonical context ID as the initial provider and preserves explicitly added references when the same ambient resource is reapplied. Unknown-resource 404s are resolved before the streaming loading boundary. No accessibility rule or permission test is weakened.

`ATLAS_APPROVED_DEV_PROJECT=hgngonpirctrwbckhbmy pnpm test:hosted` is an explicit opt-in for the approved development project. It loads only ignored web runtime configuration and runs three non-mutating checks: actual Prisma/TLS/runtime/actor cleanup through both hosted pooler modes, plus actual Auth settings and anonymous/private-schema Data API denial. No users, mail, migrations or research records are created. It does not replace actual hosted signup/recovery journeys. Hosted secrets never enter CI.

## Executable checks

`pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build`, `pnpm db:validate`, `pnpm format:check`; then `pnpm exec playwright install chromium` once and `pnpm test:e2e`. Containers that ship a different Chromium can set `PLAYWRIGHT_CHROMIUM_EXECUTABLE`; CI leaves it unset. Playwright launches a production app on 127.0.0.1:3100; it must be built first. Standard CI runs all checks. Browser plugin is not installed in this session, so regular Playwright Chromium is the recorded browser QA path.

## Conventions

Unit `*.test.ts` tests pure validation/error/contract behavior. Component `*.test.tsx` uses Testing Library, role/name queries, user-event and jest-dom. Prefer observable semantics over implementation snapshots; mock only external boundaries (Next navigation, provider SDKs) and keep deterministic fixtures. Tests must assert behavior/failure paths, never just truth or class implementation. Fixture IDs, sample labels and UTC timestamps are fixed; tests do not call paid services.

Integration tests use a new isolated Postgres DB and real constraints/transactions. `tests/database/constraints.sql` rolls back synthetic data and checks cross-org/workspace membership rejection, unique grants, restricted deletion and RLS denial. Run only against an explicitly disposable target. Phase 01 adds real actor policy tests, Auth callback/session tests and pooler isolation tests. Portable Phase 00 RLS default-deny is not a production policy suite.

E2E `*.spec.ts` tests browser → Next route → rendered response. Phase 00.5A specs are `foundation`, `phase-00-5` and `phase-00-5a`, with shared helpers in `tests/e2e/helpers.ts`; the theme is pinned through `localStorage` because the default is dark. They cover: entry to sample overview, active navigation, theme persistence/system, navigation search keyboard interactions, focus trap/Escape restore, notifications, selectors, mobile drawer and responsive overflow, unknown route/ID/module, axe accessibility on 17 routes in light and dark, the 1440/1280/1024/768/390 overflow matrix, the five Atlas AI modes, mention/slash context, share, version history, home grid/list, manuscript layouts, narrow drawers and sheets, and no-fake-functionality checks (compile, download, invite, restore, checkout, auth). No API/data boundary exists in the preview; do not pretend it was tested. Browser console runtime errors fail the smoke check.

Accessibility: every control has a name, keyboard-only reachability, visible focus, correct landmark/headings, aria-current navigation, modal focus management, reduced motion and AA text contrast. Axe covers detectable WCAG A/AA violations; human screen-reader usability remains a beta requirement. Test mobile 390px and desktop 1440px; manual screenshot review verifies composition and dark/light tokens.

CI failure is a release blocker. Add a regression for repaired defects at the lowest useful level, rerun affected checks, and broaden only when the change crosses boundaries. Keep traces/screenshots on failure without auth secrets or private research content. Standard tests contain no network/provider mocks masquerading as production implementation. Live provider/paid tests are explicit opt-in future work. Coverage targets focus on authorization and data integrity rather than line counts.

## Independent Phase 00.5B visual QA

`tests/e2e/phase-00-5b.spec.ts` adds real context transitions, overlay ownership/focus return, collision-bounded document pickers, docked manuscript editing/keyboard resizing, mobile reader/graph checks, measured design dimensions and six reviewed visual baselines. See [the evidence instructions](design/qa/00-5b/README.md) for `pnpm qa:reference` and `pnpm qa:visual`, which capture the original design separately from the built application. The full capture matrix and original runtime stay in ignored `.qa-artifacts/`; source, manifests, reports and six baselines are committed. Screenshots use separate `darwin` and `linux` directories, retaining the 0.2% tolerance and independent geometry/interaction checks. The Linux baseline comes from master CI run 39747560388, at commit 3003a2a, after all six images were visually compared with the reviewed macOS composition. The failure was text rasterization, not layout drift. New platform baselines require review; missing snapshots fail. CI uses its pinned Playwright browser. `PLAYWRIGHT_PORT` selects an unused local loopback port without reusing an unknown server.
