## Daily behavior

Inbox distinguishes assignments, replies and mentions with compact labelled icons. A selected update explains the current authorized target, sender, project, current message excerpt and real related research cards. Opening a task or notification target waits for acknowledged read state; failure retains the selection and permits retry. Message notifications open the exact original message, including one outside the latest 50; the existing cursor conversation API loads its context and highlights it. Source/annotation/document cards reuse the existing project/version/location links. Unknown historical senders are labelled “Sender not recorded”; none is inferred from an unrelated edit.

Unread/All and event filters operate on server queries, with 30-item cursor pages and full scoped counts. A server timestamp snapshot keeps newly arriving updates out of the page being read; a Show latest action explicitly admits them. Selection remains available when its row moves out of the unread filter. Tab-scoped view/cursor/selection/scroll are restored per account. Poll/focus refresh preserves keyed rows and scroll; narrow views provide a clear list/detail return with keyboard focus handling. Read/unread acts on the recipient's own row. “Mark this page read” applies exactly to the displayed IDs, leaving other pages and concurrent arrivals alone. Read retries preserve the original acknowledged timestamp. Existing event/recipient uniqueness prevents duplicate delivery on replay. The sidebar now reads a complete unread count, not a capped 100-row content list.

Target projection rechecks current project access before looking up any sender name, title, excerpt or cards. A revoked or unavailable target retains a generic recipient notification row with all private context null/empty. Opening a link still performs the target's own access check. The old Inbox array response remains for existing consumers/tests; the new UI always uses explicit paged responses.

Account Settings has Profile, Appearance, Notifications, Security & sessions and workspace navigation. Name updates preserve typed text on failure, acknowledge saving and refresh the shared identity display. Sign-in email/credential operations and session revocation remain separate. Appearance preserves the existing `atlas-theme` browser preference, verifies storage before saying saved, and reports a recoverable storage error. Only Light/Dark are offered; no unsaved writing-font or pretend preference is shown.

Only future assignment/reply/mention delivery is configurable. Preferences are saved server-side with revision review on a concurrent change; existing Inbox history remains. Muted mentions do not fall through into duplicate reply notifications. Email is explicitly disabled, with no active email/push/quiet-hours controls. Workspace details/admin membership appear only for their actual roles; ordinary members get a useful read-only explanation and links to accessible project settings. Project settings separate human-authored purpose, members/invitations, workspace navigation and administration. Existing invitation capability checks, ownership/recent-sign-in rules and recovery actions remain intact. Settings is reached from account/project menus, not added to primary research navigation.
