# Connected research workspace

10 November 2026 owner-requested increment from main `32065c0` (Inbox/Settings). It extends the existing WorkspaceProvider/WorkspaceShell and existing module services. There is no second AppShell, new design system, database migration, dependency, realtime/delivery service or infrastructure change. Email, S3 and paid AI remain disabled.

## Common navigation and work integrity

Personal Home/Inbox, the selected workspace/project, and project Overview/Library/Documents/Tasks/Discussions now have explicit, consistent scope and selected navigation. Members/Settings remain reachable through account/project menus. Discover is a Library inner view; the legacy Discover URL redirects there. Personal pages retain an explicitly selected, currently accessible project context, rather than silently choosing the first available project. Sidebar collapse is a per-account browser-tab preference.

Working tabs use workspace/project + resource kind + immutable object ID. Source metadata and its PDF share one source key; the most recently used authorized version/page/annotation locator updates that tab. Documents, tasks and discussions use their real IDs. A project Library and its Discover view share one module tab. Reopening updates the existing tab in place, without recent-visit reordering. There is no ten-tab eviction or other automatic count ceiling. Horizontal overflow, a visible desktop/narrow page menu, close controls and explicit move-left/right actions (also Alt+Shift+Arrow) keep all open work accessible.

Tab preferences contain only sanitized internal paths and identifiers/locators. Titles, quotes, provider results, question text and document bodies are not copied into them. Legacy tab hrefs migrate with duplicate object keys combined and private labels discarded. Titles are resolved afresh by authenticated server reads; unavailable targets disappear. Tabs from another project are retained as identifier preferences but hidden outside that project scope. Account changes cannot restore another account's titles or content. Current-project and item checks still run at every content endpoint.

The navigation safety bridge uses the existing acknowledged document flush/recovery and serialized PDF-position save. Links, working-tab close, project selection, related-object creation and browser Back/Forward respect pending work. Document navigation drains slow acknowledgements and edits typed during saving. If saving fails, the route/tab stays open; retry/stay and an explicit verified existing document-recovery choice are offered. Failed browser storage does not count as recovery. Existing recovered-draft review remains mandatory when reopening; no new document-content preference store is added. Task edits are acknowledged before shared navigation. Full reload keeps the existing browser warning/recovery behavior. Browser history fields belonging to Next are preserved alongside a navigation index; filtered list URLs remain intact on replay. Library reads its existing account/project filter preference when revisited through a plain module link. Reader and Editor keep their existing exact version/position and recovery/history semantics.

A single provider-owned AI companion remains mounted for a selected authorized project while moving through its research pages, Home/Inbox and same-workspace settings. Presentation changes reuse the composer, conversation, draft, preview and dispatch state. Options refresh on research changes and when the AI surface opens, fixing the stale “add a PDF” message after a new import. Menus/dialogs compact the same surface; native modal focus takes priority. A different project/workspace requires explicit review of an unsent in-memory draft or an outstanding acknowledgement; no old project text is silently displayed in the new scope. Returning to a permitted project restores its real server conversation ID/history, not a duplicated conversation. Inbox page controls reserve space above the compact shared island.

## Shared search

Cmd/Ctrl+K and the sidebar open one provider-owned shared search dialog, including on personal pages. Its query survives a page transition already in progress; a per-page shell remount no longer silently closes it. Server-side queries search active accessible projects, source titles/authors/DOIs, document/task/topic titles and live PDF-note text. Results have real project/workspace context and target links, including exact annotation version/page, with complete counts and explicit 25-result pages. No first-page object list is presented as the entire result set. Runtime RLS selects candidates; scope locks/current resource reads resolve every visible title. Unknown/denied tab targets return no label. Archived work remains accessible through the existing module views/direct permitted links; global search is an active-work search, not full-text/semantic search across every PDF or document body.
