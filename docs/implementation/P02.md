# Phase 02 implementation record

The owner’s 9 November 2026 request authorizes one integrated research-library delivery and deployment to the existing Atlas application in Coolify yula.co. It supersedes G01-as-entry-gate and per-slice comprehensive reviews. Deferred evidence remains in [the beta backlog](../BETA_REVIEW_BACKLOG.md); Phase 03 is excluded.

## Data and authorization

Migration `202611090005_library` is additive and atomic. Source and annotation artifact UUIDs support later same-project references. Composite foreign keys bind source, version, file, collection and annotation to the same workspace/project. Bibliographic metadata is editable with optimistic revisions; version/file identity and annotation anchors are immutable. DOI normalization, canonical http(s) links and per-project uniqueness return the existing source on repeat addition. Identical file hashes within a source return its existing version.

All private tables enforce FORCE RLS. Application reads/writes use identity/session, scope locks and live project roles. Owners/admins/editors write shared research; viewers read/export and save only their own reading state. Annotation edits are author-only or owner/admin. Archived project writes are denied. Jobs recheck the original actor/session before content read and result write; expiration/revocation cancels processing. Queue credentials cannot read file/source content. No PDF bytes are stored in PostgreSQL or public assets.

Stable routes: `/w/:workspace/p/:project/sources/:source`, `/read?version=:version&page=:page&annotation=:annotation`. Annotation records contain source/version/page/quote/normalized rectangles; they never move to a replacement PDF. File access uses the authorized `/api/research/:workspace/:project/sources/:source/versions/:version/file` route including HEAD and single/suffix range requests. Binary/export responses are private, no-store.

## Provider and libraries

Crossref is the sole metadata provider. Its [official access documentation](https://www.crossref.org/documentation/retrieve-metadata/rest-api/access-and-authentication/) permits public access without registration/API key; current public list limits are 1 request/second and concurrency 1. A PostgreSQL lease serializes requests across app processes, retains at least one second between starts and recovers after a bounded request timeout. Requests identify Atlas by its public repository, without disclosing the account owner’s email. No paid pool is used. Fetch is restricted to fixed `api.crossref.org/works` endpoints, no redirects, 10-second timeout and 2 MB response limit. User-provided arbitrary article/PDF URLs are not downloaded by the server. Search terms are sent to Crossref when the user searches.

Crossref supplies bibliographic metadata, often incomplete. Provider provenance is recorded, abstracts are displayed as plain text, and missing values remain empty/editable. The [REST overview](https://www.crossref.org/documentation/retrieve-metadata/rest-api/) distinguishes metadata from publisher abstracts and full text: discovery does not grant a PDF license or full-text access. Users upload PDFs they may use. No provider responses/papers are committed.

PDF.js `6.5.438` is pinned (Apache-2.0); worker/fonts/cmaps/wasm and license are copied locally at build, with no CDN. The [PDF.js API](https://mozilla.github.io/pdf.js/api/draft/module-pdfjsLib.html) and [rendering examples](https://mozilla.github.io/pdf.js/examples/) informed canvas/text-layer integration. PDF actions/forms/XFA are not rendered. Server extraction uses Debian Poppler in the bounded files container; see [ADR 0004](../decisions/0004-files-jobs-and-realtime.md).

## Product surfaces

Existing project overview/sidebar now lead to Research and Library. Crossref search has pagination, details, saved state and a manual fallback. DOI lookup, article link, manual fields and direct PDF selection share the add-source form. Metadata-only sources remain useful. Library search/filtering applies before pagination; collections/tags are shared, reading state is personal. Reader supports page/zoom/text search, selectable text, persisted highlights/page notes, per-version note lists and personal position. Narrow layouts use a notes dialog instead of squeezing the PDF. BibTeX/RIS use actual fields and stable source identifiers. No AI placeholder or future-module controls are introduced.

The latest supplied Atlas HTML hash and precedence are in [REFERENCE](../design/REFERENCE.md). Sidebar 240 px, collections 184 px, compact toolbar, warm sidebar/white canvas and blue accent follow the reference. Necessary adaptations: real upload/error/version states replace prototype-only controls; notes become modal below 1200 px; future AI/tools are omitted. This is reference-guided implementation, not a claim of pixel parity or completed beta accessibility review.

Verification and deployed commit are recorded in [the Phase 02 handoff](../PHASE_02_HANDOFF.md). Broad security/load/browser/accessibility/restore/rollback checks are explicitly deferred.
