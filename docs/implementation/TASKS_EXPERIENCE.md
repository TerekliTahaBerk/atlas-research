# Tasks experience

Owner-requested increment, 10 November 2026, based on Documents release `52759fd`. Tasks only; existing task, permission, artifact and Inbox services remain the foundation. The current Atlas.dc.html (`fb98b5ca09dc1bf7fdb49aec20ad47ba2c49f0ca0ac61a7cd4822a30b90db53d`) and actual controlled tasks were compared at 1440×1000. The supplied reference sets the 260 px cards, 20 px column gaps, 420 px detail rail and status colors. Prototype ticket numbers, activity, avatars and AI are not fabricated.

## Delivered

- Compact Board/List, shared search/filter/sort and title-only creation from the toolbar, column or List. Optional fields are available without blocking first capture. Enter/Escape, duplicate-submit guards and retained retry payloads apply to creation, including existing PDF-note/document context.
- Real native dragging changes status and persists the exact insertion position. The visible card remains at its acknowledged location until the server accepts the move; failure retains the card and retry action. Board order enables dragging; other explicit sorts retain their meaning. A card menu provides keyboard-accessible status changes. Narrow screens default to List and offer one-column Board navigation.
- List status, eligible assignee, priority and date are directly editable. Date changes save on blur/Enter; dates remain calendar strings. Overdue excludes completed tasks. Server-side title/description search, combined status/assignee/mine/unassigned/priority/date filters, explicit completed visibility, real filtered counts and pagination replace the Tasks page's former silent 300-row cap. Board pages contain 30 per column; List pages contain 50. Preferences and return context are account/project scoped.
- Desktop task rail and narrow dialog preserve the working list. Stable detail links work from Inbox and discussions. Revision conflicts retain local edits and show the latest task; users explicitly review changed fields before saving against the new revision. Research search selects real authorized project sources, annotations, documents and discussions; existing backlinks and immutable PDF locators remain. Only active editor-or-higher members can be assigned. Existing assignment Inbox events are reused.
