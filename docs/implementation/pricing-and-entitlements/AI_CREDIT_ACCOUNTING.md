# AI credit accounting

Atlas prices the existing grounded assistant through an immutable provider rate version. Version `openai-standard-global-2026-11-23` covers one synchronous, standard-tier, text-only Responses request on GPT-6 Luna. It meters ordinary input, cached input, 30-minute and 12-hour cache writes, and output tokens including reasoning. It stores integer USD micros. The registry records USD nanos per token so fractional rates and intermediate totals stay exact. The response cost rounds up to the nearest micro. [Official GPT-6 Luna pricing](https://developers.openai.com/api/docs/models/gpt-6-luna), [cache meters](https://developers.openai.com/api/docs/guides/prompt-caching), [Responses schema](https://developers.openai.com/api/reference/resources/responses/methods/create).

## Admission and settlement

1. The preview shows exact authorized question and evidence, whole-credit ceiling, provider cost ceiling, and policy. The client submits the ceiling and its pricing version alongside scoped consent.
2. Atlas validates both values against the frozen context and active provider policy, acquires workspace and actor locks, admits at most two concurrent jobs per workspace and one per actor, and checks the independent workspace day cap. With resource enforcement enabled, the shared ledger checks the member daily entitlement, the workspace wallet, the team member share and expiring top-ups. The reservation and run are created in one transaction.
3. The provider request uses `store: false`, standard tier, 30-minute cache policy, no tools, a 50,000 UTF-8 byte envelope limit, and 2,000 maximum output tokens. The reserve uses 60,000 input tokens, wholly priced at the 30-minute cache-write rate, plus 2,000 output tokens. Its maximum for the current model is 8,500 USD micros and one credit. Envelope-to-billed-token headroom is conservative, and deployment still requires a real provider meter acceptance run. Provider dispatch and delivery check permission, the workspace policy revision and current index availability.
4. An eligible answer or valid abstention settles at `max(1, math.ceil(provider_micros / 10_000))`. Validation failures, dispatch errors, cancellations and lease expiry return credits. Provider charges received for unusable answers are still recorded. If a dispatched call has no valid usage receipt, Atlas retains the full provider reserve as an uncertain cost. The queue releases abandoned credit holds without reading research content. There are no automatic provider retries.
5. An approved billing operator sees the monthly provider aggregates and high-cost run metadata. A separate trusted migration-role reconciles uncertain provider spend using `ops.reconcile_ai_provider_cost(run_uuid, receipt_reference, confirmed_micros)`. Supply an opaque provider invoice/reference code and the confirmed amount from an external billing record. A repeated identical reconciliation succeeds without a second receipt. This updates provider accounting while leaving the member's refunded credits and research history intact.

The platform's Founding program shares a separate USD 180 provider budget per UTC calendar month. A serialized guard includes actual, uncertain, and active reserved cost for all founding runs admitted in that month. At 80 percent the AI usage UI and admin report warn. At the ceiling Atlas refuses additional reservations. The paid or pilot user-credit period follows that entitlement's own renewal boundary.

## Rollout

Paid calls still require the existing explicit web environment gate and a key controlled by the operator, an owner-enabled workspace data policy, a positive owner-approved daily provider budget, and a priced model. Set `ATLAS_RESOURCE_LIMITS_ENABLED=1` to enforce plan credits and daily operation quotas. Configure `ATLAS_AI_MODEL` only from the active registry. Live provider dispatch also requires the credit enforcement flag. Only the isolated synthetic loopback tests can exercise the legacy flag-off path. Keep the provider gate off until the operational budget and provider acceptance are verified. Keep prior rate versions available for in-flight run decoding when extending the registry.

Current retrieval is PostgreSQL full text over selected indexed sources. It has no provider-paid retrieval units. The current request path dispatches no paid tool calls, provider embeddings, deep-research jobs, background agent steps, Flex/Fast inference or separate regional rates. An unexpected paid tool receipt fails closed. Those capabilities need their own priced meter, scope and upper bound before they can enter this workflow. Historical conservative run amounts remain labelled as historical estimates and are outside the verified price reports. No provider account, live key, or paid model call is needed for local tests.
