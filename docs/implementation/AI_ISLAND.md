# Dynamic AI island

10 November 2026 owner instruction supersedes the earlier docked-only decision. This increment uses the existing private conversation, preview, run/cancel, budget, claim review and document proposal services. It does not enable paid calls, accept a sharing policy, create a key, or change email/S3.

## Implementation

The authenticated root workspace provider owns the single AI companion for the current user/project. Research route changes no longer unmount it. Presentation is one compact/floating/focus/docked state; draft, conversation, selection, preview and active run are independent. Minimizing does not cancel a job. History is reloaded from the server. Only presentation and a conversation ID are stored in session storage, scoped by user/workspace/project; question, selection and excerpts are not written there. Changing project or losing the current authenticated project removes the old surface.

Reference `aiBox` in `docs/design/reference/Atlas.dc.html` was read directly: 16 px floating corners, 680 px maximum floating width, 720 px focus width, 392 px dock, 18 px bottom inset or 52 px in Reader. Runtime geometry measures the main workspace and open detail/note rail; content reserves space beneath the island. Focus makes background pages inert and traps Tab, Escape returns to floating, Cmd/Ctrl+J opens the composer. Narrow layouts and VisualViewport resizing keep the composer within the visible viewport; reduced motion removes transitions. Presentation changes reuse the same textarea rather than remounting the editor.

The +/@ path opens real project research selection. Existing source-version selection remains; sources, documents, tasks, annotations and discussions can also be searched. Current-page context is added explicitly, never automatically dispatched. Changing fixed scope requires a reviewed fork. Migration 011 adds conversation artifact IDs and immutable context snapshots, preserving existing conversations. The server resolves every object in the authorized project, records document/annotation revisions and annotation PDF version/page, validates selected text against authorized indexed pages or object text, and rechecks scope at retrieval/dispatch/result/proposal boundaries. Non-PDF evidence uses its actual object link and revision; no PDF page is invented. Document proposals retain explicit review, current revision, write permission and existing idempotent apply/undo. Non-PDF references include the quoted snapshot and revision in an ordinary object link; PDF references continue to use the citation registry.

The buffered response is shown after server completion, without fake token streaming or reasoning. Existing run states/cancel and budget failures remain real. Request retry retains its dispatch ID; retrying a failed question requires a fresh evidence preview/approval. Copy uses the actual response. Answers render plain text/lists, fenced code and untrusted KaTeX math with trust disabled. Task creation starts from the selected actual answer as an editable draft and requires the normal explicit task submit.
