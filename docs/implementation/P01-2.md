# P01-2 — Doğrulanmış kimlik, oturum ve kişisel workspace

Önceki dilim [PR #27](https://github.com/TerekliTahaBerk/atlas-research/pull/27) ile `365ab6bf74b0d684ffc191e7d373841b577a3843` squash commit'inde birleştirildi. Bu dilim server akışlarıdır; tasarıma uygun kayıt/ayar arayüzleri P01-4, canlı SMTP ve Coolify kanıtı P01-5'tedir. G01 henüz kapanmadı.

## Çalışan davranış

- Better Auth e-posta/parola, zorunlu doğrulama, bir saatlik doğrulama bağlantısı, 15 dakikalık tek kullanımlık reset ve reset sonrası DB session iptali. Cookie cache kapalı, hassas işlem freshness 5 dakika. Library parola/hash/session mantığı değiştirilmedi. Verification identifier hashing kütüphanenin desteklediği seçenekle açık.
- Üniversite alan adı gerektirmeyen hesap; duplicate signup ve bilinmeyen/bilinen hesap reset cevapları generic. Profil yalnız kendi name alanını günceller; uygulama session listesi token yerine session ID ve süre verir; iptal own ID→library revoke yolundadır.
- Auth POST girişinde tüm istekler için exact Origin, cross-site/content-type ve 8 KiB gövde kontrolü. Better Auth DB rate limiter ve Retry-After; production reverse proxy'nin `x-real-ip` başlığını istemciden bağımsız yazması dağıtım önkoşulu. Yoksa tüm istekler tek kısıtlı bucket'ı paylaşır.
- İlk doğrulanmış oturumda kişisel workspace ve owner üyeliği tek transaction'da, kullanıcıya özel transaction advisory lock ve unique owner kısıtıyla oluşturulur. Eşzamanlı tekrar aynı boş workspace'i verir. Personal tablo politikaları ENABLE/FORCE RLS; app actor + session context geçerliliği ve güncel DB expiry birlikte denetlenir.
- SMTP kuyruğu özel identity şemasındadır. Adres, bağlantı ve gövde AES-256-GCM ile şifreli payload; gönderim sonrası payload temizlenir, expiry'de silinir. Worker lease/retry ve sabit message ID kullanır. SMTP at-least-once olduğundan crash sonrası tekrar mail mümkün; ürün işlemi tekrar uygulanmaz. Auth e-posta callback'i kütüphane sınırında durable enqueue yapar; auth transaction'ıyla atomik commit iddiası yoktur. Başarısız kayıt/teslimde kullanıcı generic yanıt sonrası yeniden doğrulama isteyebilir. Proje davetinin domain+outbox atomikliği P01-4'te uygulanacak.

Mail worker ayrı compiled Node süreci: `npm run build` sonrası `npm run mail:worker`. SMTP secret/body/token/response loglanmaz; failed log yalnız outbox ID'dir. Production SMTP'de implicit TLS veya zorunlu STARTTLS ve sertifika denetimi; local test SMTP yalnız loopback'tedir. Secret rotation sırasında eski şifreli bekleyen mail çözülemez; süre sonunda temizlenir ve kullanıcı yeni bağlantı ister. Existing secret'lar bu çalışma sırasında değiştirilmedi.

## Gerçek kontroller

PASS: `npm run verify` — typecheck, lint, 3 unit test, disposable PostgreSQL 18.6 + gerçek kontrollü SMTP üzerinde 4 integration test ve DB/secret gerektirmeyen production build. Testler:

1. Doğrulamasız giriş reddi, gerçek SMTP verify, duplicate signup, şifreli outbox, profile update, aynı W0'a iki eşzamanlı istek, reset bilinmeyen/bilinen cevap eşliği, token replay reddi, eski session/password iptali ve DB expiry.
2. Cross-origin ve oversized body reddi; DB-backed 5/60s sınırı; Secure/HttpOnly/SameSite cookie; başka kullanıcının session'ını iptal edememe; kendi iptali; kişisel workspace çapraz erişim reddi ve pool context'in transaction sonrası boş kalması.
3. Gerçek Prisma + Better Auth session roundtrip/logout.
4. Atomic rollback, identity/content credential ayrımı ve DDL reddi.

İlk testler origin politikasının anonim login için daha sıkı giriş kontrolü gerektirdiğini ve library'nin Retry-After vermediğini gösterdi; app boundary düzeltildi. Library'nin başka session token'ına generic success cevabı, uygulama servisinde own session ID kapsam kontrolü ve ikinci hesabın session'ının değişmediği kanıtla doğrulandı. Testler salt mock değildir.
