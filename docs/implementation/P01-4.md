# P01-4 — Real user flows and Atlas shell

Implemented S01–S05/S15/S16: sign-up/verification/sign-in, resend/reset, empty personal onboarding/home, shared workspace and private project creation/switching, invitation preview/acceptance, project/member roles and revocation, owner transfers, archive/deletion recovery, profile/theme/session settings and safe unavailable/retry screens. No demo data or later-phase controls are shipped. Deep invitation links preserve the target through registration and verification; return paths are restricted to application routes. Sensitive flows use a full navigation to discard previous session state. Client reads are no-store, refresh on focus/every 20 seconds and refresh other scopes after access denial; this polling is a UX measure, never server authorization.

The current Claude design was reopened and visually inspected, then compared with rendered light/dark screenshots. Fidelity ledger:

Source screenshot was observed in the browser; implementation screenshots were inspected with the image viewer. This is a reference-based shell, not a claim of pixel parity for unspecified auth/governance screens. No new visual concept or generated asset was introduced. D01–D06 applicable changes include meaningful labels, visible input focus, reduced motion, contrast corrections, named icons, native route navigation and modal focus handling. No AI panel exists in this phase. Real screen-reader testing and browser-native 200% zoom remain NOT RUN; 320px reflow is an additional local check, not a substitute for assistive-technology validation.

`npm run verify` now includes production-build browser QA in a second disposable PostgreSQL/SMTP environment. Browser plugin not available; regular Playwright Chromium is used. Three independent browser contexts register, receive controlled SMTP verification mail, sign in and start empty. A creates a shared workspace/project; B accepts the exact email invitation; C cannot open it; B becomes viewer then loses access after revocation. Profile update, reset with old-session invalidation, session revocation, anonymous state and network-error retry are exercised. Four widths (390/768/1024/1440), two themes and six screens produce 48 temporary synthetic screenshots outside the repository. No framework overlay, relevant console error or horizontal app overflow is allowed. Keyboard drawer cycling and focus return are assertions. Tokens/passwords are memory-only and are excluded from error logs and screenshots.

Browser QA caught and fixed a real Next Request-body reconstruction failure on sign-up and a native-dialog Tab wrap issue; adapter-only smoke tests were insufficient. `tests/unit/contrast.test.ts` checks actual stylesheet tokens rather than a duplicate palette. Production build requires no DB or secrets. `playwright@1.65.0`, `@playwright/cli@0.1.23`, `prettier@3.9.10` are pinned dev tools. ESLint remains 10.14.0: upstream Next lint plugins still declare peers through 9.x and npm warns; lint actually passes. ESLint 9.39.5 was evaluated but is marked unsupported by npm, so it was not retained. This tooling peer-declaration limitation is open; it is not a runtime compatibility claim. Frozen install reports zero known vulnerabilities.

Local verified flows are distinct from external SMTP delivery and Coolify acceptance. Deployment target is the user's **yula.co** project; no production resource has been changed. G01 remains open pending P01-5 live evidence.
