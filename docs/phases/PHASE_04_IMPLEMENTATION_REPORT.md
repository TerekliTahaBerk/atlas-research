## Root causes and implementation changes

**Archive recovery:** archived rows linked to the ordinary document route; `getDocument()` deliberately rejected archived content. The editor's existing restore control therefore could not be reached. The fix keeps archived rows metadata-only and moves the recovery action into the listing. The browser regression first verifies that the ordinary route and history endpoint are unavailable, then recovers through the listing and reopens the normal editor. Unauthorized and stale-version command attempts are tested against PostgreSQL.

**Task visibility:** `listTasks()` already returned a bounded page and signed `nextCursor`, but `live-tasks.tsx` stored only the first page. The shared page hook now retains and follows the cursor. No server pagination API or schema change was needed: default task-number ordering is already deterministic. Both layouts show loaded counts and a more-results indicator. Status rollback changes only the failed task, preserving concurrently appended rows. Background reconciliation keeps task controls mounted, fixing a menu-detachment regression found by running the original task E2E journey during development.

**Autosave lifetime:** cleanup cleared the current timer, but a still-running request could schedule a new debounce/retry after cleanup. The captured lifetime now guards both completion branches and subsequent saves. An already-dispatched transaction can still commit; the retained draft is reconciled with the server when reopened.

## Limitations and Phase 05 handoff

- Offset pagination is deterministic but not a database snapshot. Concurrent archival/deletion or filter membership/sort-key changes can shift offsets and temporarily omit rows; duplicates are removed. Own mutations re-fetch loaded pages; reopen to reconcile external churn. Revisit keyset/snapshot paging when measured collaboration needs justify it. See [task model](../tasks/TASK_MODEL.md).
- Progressive loading retains fetched rows in memory and renders them without virtualization. The 500-task journey passes; no unlimited-scale claim is made. Graph projection remains bounded at 300 nodes/1,000 edges and discloses truncation.
- Two tabs share one latest local draft per actor/project/document; browser storage can be unavailable and drafts expire after seven days. Existing account/sign-out purge remains deliberate. No CRDT/realtime co-editing is introduced.
- Scientific validity of real-model output, hosted recovery, hosted HTTP denial, scanner/extractor deployment, non-Chromium browsers and human screen-reader testing remain unverified release work.
- Phase 05 can plan against stable artifact IDs, revision retention, same-project typed links and live capability checks. Channels/messages require their own reviewed persistence, membership, private Realtime, reconnect/backfill and notification boundaries; links never grant access. No Phase 05 code has been started.
- Local code verification is PASS. Final PR readiness still requires successful hardening CI as recorded above. Hosted operation remains BLOCKED even after code checks pass; merging code does not authorize hosted activation or deployment.
