- **R11-01 / P2, existing defect still present:** `use-autosave.ts` catches NETWORK/CONFLICT and resolves `Promise<void>`. `LiveDocument.keepMine()` awaits `saveOnTop()` then always flashes “Your draft was saved as a new revision.” A second conflict or failed network save therefore produces success feedback without a committed revision. The status/draft remain failed/preserved, but the completion message is false. Existing on-disk master has the same defect; it was not introduced by PR #11. It is relevant to the requested autosave recovery review and must be corrected in that PR or a separately scoped recovery follow-up before approving that behavior.

Two independent regression probes on the archived PR source reproduced R11-01 (both FAIL as expected): mock `artifactCommand` to reject with CONFLICT or NETWORK; render `useAutosave`; `await saveOnTop(2)` in the same try/success/catch structure as `keepMine`; status becomes conflict/offline, yet the success spy is called once. The unchanged 223-test suite passed before adding those probes. The initial archived test run had a missing package symlink; correcting only the review harness produced the full PASS. No PR source was copied into the A00 branch.

Minimal requested correction: expose an explicit confirmed-save result or throwing explicit-save path, keep background debounce failures handled, and announce success only for a confirmed recovery commit. A no-op caused by an already in-flight save must not count as confirmation. Add caller-level success/failure tests and retain the existing offline draft/unmount guarantees. Also audit `restoreRevision()`'s awaited save and captured revision for the same result-contract assumption. No additional restoration defect is asserted without a reproduction.

Reproduction to add to PR #11's existing `autosave.test.tsx` (reuse its mocks/options):

```tsx
it.each(['CONFLICT', 'NETWORK'] as const)(
  'does not confirm recovery after %s',
  async (code) => {
    vi.mocked(artifactCommand).mockRejectedValue(
      new ApiError('save failed', code, code === 'CONFLICT' ? 409 : 0),
    );
    const { result, unmount } = renderHook(() => useAutosave(options));
    const success = vi.fn();
    await act(async () => {
      try {
        await result.current.saveOnTop(2);
        success();
      } catch {
        // The current caller presents failure here.
      }
    });
    expect(result.current.status).toBe(
      code === 'CONFLICT' ? 'conflict' : 'offline',
    );
    unmount();
    expect(success).not.toHaveBeenCalled();
  },
);
```

This captures today's incorrect void-result contract; adapt the caller assertion to the explicit result chosen for the correction.
