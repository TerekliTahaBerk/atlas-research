# Conversations and streaming

Conversations are project-scoped and creator-private. Persisted runs contain the user/assistant message pair, references, evidence snapshot, selected provider/model, finish state and usage. Lists return at most 50 conversations; history returns the most recent 40 pairs. Model context uses only the last four completed pairs, truncated to 2,000 prompt and 4,000 answer characters each, plus the current bounded evidence. Old evidence is reauthorized before history is returned or reused.

Authenticated same-origin `POST /api/v1/ai/runs` streams SSE. Events are `run.started`, `retrieval.started`, `retrieval.completed`, `response.delta`, `citation.verified`, `usage.updated` and a terminal `run.completed`, `run.failed` or `run.cancelled`. `runStreamEvent` defines schemas. Provisional text has no final verification status. Revocation can produce a minimal `run.failed` envelope without content. Successful final state is committed before delivery.

SSE is attached to the submitting POST; there is no detached background generation or exactly-once provider guarantee. Recovery uses authorized `GET /ai/runs/:id` snapshots or conversation history, not automatic token replay. A repeated actor/idempotency key returns the saved run and never dispatches the provider again; changing its payload conflicts. Explicit “new attempt” uses a new key and may incur usage. A one-second heartbeat observes cancellations/revocation and aborts work; the request has a 120-second deadline. Three-minute abandoned run leases become UNCERTAIN after dispatch or CANCELLED before dispatch when reconciled. No uncertain dispatch is silently retried.

Rename/archive/delete use optimistic conversation versions. Archive hides the conversation from the list and keeps records. Explicit delete erases prompt, answer, evidence, references and relational citation quotes, while retaining minimal run/provider/usage identity for accounting. `ATLAS_AI_RETENTION_DAYS` defaults to 30 (1–365); listing conversations runs actor-scoped expiry cleanup. This is read-triggered cleanup, not a guaranteed background retention schedule. A deployment requiring guaranteed timed erasure must schedule the reviewed retention service under separately approved operations. Source Library records are unaffected.
