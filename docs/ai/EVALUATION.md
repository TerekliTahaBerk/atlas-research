## Exact opt-in low-budget smoke procedure (prepared, NOT RUN)

This procedure requires a later explicit approval naming the provider accounts, models, public/synthetic inputs and a **combined maximum of USD 0.50**. It does not enable traffic now. Complete the hosted activation gates first if using a hosted app; an identified disposable local live app may instead be used with its independently approved runtime. Use the credential skill to select/store keys securely at that time; never paste keys into commands, prompts or reports. Ordinary CI remains fixture-only.

1. Review current official OpenAI and Anthropic pricing/model access and retention settings. Choose one approved text model per provider, sequentially, with no fallback/retry. Configure `contextTokens=8192`, `maxOutputTokens=256`, reviewed integer micro-USD tariffs and `ATLAS_AI_MONTHLY_LIMIT_MICROS=250000` (USD 0.25) for each **separate isolated ledger**. Compute `ceil((7936*inputMicrosPerMillion+256*outputMicrosPerMillion)/1000000)`; require at most 25000 micro-USD per generation. With at most six calls per provider, generation reservations total at most USD 0.15 each; leave USD 0.10 each for separately bounded indexing/query embeddings and uncertainty. Do not reset/reuse the budget ledger to bypass a cap. Provider account budgets/alerts are additional safeguards, not assumed instant hard stops.
2. Use exactly two short synthetic/public saved papers (one passage of at most 256 UTF-8 bytes each) with known immutable passages and different conclusions, including an explicit limitation and a clearly adversarial instruction inside one passage. Index only these bounded inputs. Confirm the engine's conservative request bound, including instructions/schema/history, fits the configured context before dispatch; shorten the prompt or use a fresh conversation if it does not. Approve both generation and embedding credentials/data policy and include all embedding reservations in the same USD 0.25 provider ledger. If the indexing estimate cannot fit, stop and use metadata-only evaluation with its reduced claims. Explicitly enable paid requests **only after** that later authorization; set the approved provider/model policy for the first isolated app and ensure fixture origins are unset. Obtain sessions through the normal browser login; do not export cookies.
3. Submit the six scenarios below in the live UI, once each, with new idempotency keys only for new requests. For a duplicate-submit check, reuse the exact original request key/payload through the existing request inspector without sending another new run. Keep at most one active run. Record safe run/request IDs, state, source-location pass/fail, unsupported-claim count, input/output tokens, reservation/settled micro-USD and latency. Review scientific claim support manually against the known passages. Do not log full provider payloads, keys, sessions or signed URLs.
4. Repeat against the second provider in its separately isolated ledger, keeping the **combined ceiling USD 0.50**. Stop immediately on quota, unexpected billing, unauthorized context, a fabricated verified location or incorrect final success. Disable paid dispatch and unset activation afterward. Reconcile recorded usage with both provider dashboards/invoices; uncertain/cancelled dispatch retains its reservation until investigated. Report factual PASS/FAIL/NOT RUN per scenario; a failure is not a reason to retry automatically or increase the budget.
