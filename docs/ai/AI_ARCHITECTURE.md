# Atlas AI research architecture

Atlas AI is part of the existing modular monolith. `packages/ai` owns Zod contracts, source chunking, exact citation verification, provider interfaces and server-imported execution adapters. It imports neither database nor UI. `features/ai/server` owns actor-scoped orchestration and database repositories. The five existing Atlas placements share `AtlasProvider` and one live conversation hook; preview mode retains its separately labelled samples.

A request passes verified Supabase identity, origin/JSON limits and SQL rate buckets, then resolves every attachment under current RLS. The server validates its configured model policy, reserves a conservative maximum cost atomically, optionally embeds the query, retrieves authorized evidence, and rechecks the evidence. Only bounded history and relevant passages enter the provider request. The provider returns schema-constrained JSON; provisional text is streamed before exact citation verification. Completed answers and relational citations are persisted before the final event. Tool execution never originates from arbitrary model output.

`ai_runs` persists a user prompt and its assistant response as one ordered pair; `ai_usage` combines reservation and settlement in one operation record. `source_chunks` stores the immutable extraction and fixed-dimension embedding together. See [ADR 0016](../decisions/0016-ai-research-engine.md) for these deliberately consolidated entities.

Hosted operation is disabled until security and recovery activation is reviewed. Isolated tests use real PostgreSQL/pgvector and official SDKs with synthetic loopback wire responses; these responses are not real inference. [Activation](../phases/PHASE_03_ACTIVATION_PLAN.md), [evaluation](EVALUATION.md) and the [implementation report](../phases/PHASE_03_IMPLEMENTATION_REPORT.md) separate local evidence from external gates.

The hardening migration `20261023170000_ai_stream_authorization` consolidates source/reference checks into SQL invoker functions and makes run RLS authoritative for snapshots, history, minimal streaming state and final output. Fast deltas coalesce at 256 characters/50 ms; each emitted batch has a fresh database gate and idle streams retain a one-second heartbeat. Follow-ups bind bounded, transitive historical provenance in `context_json`, including the sources of earlier answers. Archiving or changing those sources hides dependent runs and terminates further delivery. See [measured performance and limits](STREAMING_PERFORMANCE.md).
