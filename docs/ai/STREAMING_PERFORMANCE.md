# Streaming performance and live authorization

Measured 23 October 2026 on Node 24.21/PostgreSQL 17/pgvector, loopback Docker (Colima, four CPUs/six GiB). Baseline code is PR head `ac50290`, eight original migrations. Hardened code uses the additional stream-authorization migration. Both use the same instrumented PostgreSQL test and synthetic provider generator. No model traffic or confidential input is involved.

| Scenario                                       | SQL before | SQL after | Transactions before → after | Elapsed before → after |
| ---------------------------------------------- | ---------: | --------: | --------------------------- | ---------------------- |
| Validate one metadata source                   |          7 |         3 | 2 → 1                       | 8 → 5 ms               |
| Validate twelve distinct metadata sources      |         29 |         3 | 2 → 1                       | 23 → 5 ms              |
| Validate twenty-four distinct immutable chunks |         77 |         3 | 2 → 1                       | 64 → 8 ms              |
| Stream 100 provider deltas                     |      4,769 |        52 | 750 → 16                    | 4,495 → 110 ms         |
| Stream 500 provider deltas                     |     23,194 |        56 | 3,618 → 17                  | 21,188 → 122 ms        |

Counts include runtime-role validation, actor-context setup and application SQL in every actor transaction. BEGIN/COMMIT are excluded (add two protocol statements per transaction). Internal statements inside SQL functions/RLS are not separate client round trips. Worker/admin fixture setup and `prepareRun` are excluded; streaming includes initial state, history, embedding reservation/settlement, retrieval/audit, generation persistence and final state. Stream evidence contains four indexed chunks from one paper. The twenty-four-chunk case separately exercises the maximum validation batch. One/twelve-source cases measure validation, not corpus search. Fixtures emit 100/500 single-character deltas without provider delay, so these numbers measure orchestration overhead, not model generation throughput, hosted latency, or large-corpus capacity. Heartbeat counts can vary with wall-clock scheduling; the latency samples are single local observations.

Previously every event ran a per-evidence loop and reconstructed several snapshots, including one per final citation. Now evidence/reference checks run as bounded SQL invoker functions under caller RLS. Snapshot/history selects trust the same authoritative run policy rather than repeating the checks in separate transactions. Delta persistence and a minimal state/version projection share one transaction. Final citation/usage events share one freshly authorized completed snapshot.

Deltas coalesce at 256 characters or 50 ms, whichever occurs first, and flush before completion/error. These bounds limit aggregation; they do not promise a 50 ms database/network response. Every emitted batch rechecks live RLS. An independent one-second heartbeat checks idle streams; the request deadline remains 120 seconds. No permission cache or actor-independent snapshot is introduced. Buffer cancellation drops pending output and interrupts stalled reads.

Follow-up context stores deduplicated historical evidence/references in `context_json`. Every subsequent read/batch/final snapshot checks that provenance too. This closes a gap where archiving a source used in a prior answer could otherwise leave a follow-up readable. Historical dependencies are capped at 120 evidence items and 60 references; exceeding the cap requires a new conversation. Erasure/retention clears the added provenance. This migration precedes hosted AI activation; pre-hardening local fixture runs have no inferred/backfilled ancestry.

`tests/integration/ai-research.test.ts` counts actual actor SQL calls through a test-only transaction proxy without recording statements/values. CI requires exactly three SQL calls/one transaction for each evidence batch and at most 90 calls/25 transactions for each burst stream. Latency is reported, not asserted against machine-dependent thresholds. Unit tests verify burst preservation, 50 ms flushing, stalled reads, abort cleanup and event ordering. PostgreSQL tests verify revocation, historical-source archive, canonical evidence fields, final citations, disconnect, timeout and single settlement. A slow provider still requires one fresh authorization check per emitted batch; coalescing does not bypass it.
