# Embeddings and retrieval

OpenAI and Google implement the provider-neutral embedding contract. Outputs must contain exactly one finite, nonzero 768-dimensional vector per input, in stable order. The index key is `provider:model:revision:768`; provider, revision, dimensions and generation timestamp are stored with each chunk. Operators must change the revision and reindex when embedding behavior changes. Incompatible index keys are never searched together.

The additive migration installs pgvector in `extensions`, failing for an unexpected preexisting extension schema. Project/source indexes and a GIN full-text index accompany the fixed-dimension vector column. Retrieval materializes RLS-authorized, same-project, active-paper, READY-source candidates before cosine ranking. It combines cosine similarity (0.7) and simple-dictionary full-text relevance (0.3), with stable UUID tie ordering and per-paper round-robin contribution. This initial implementation uses exact vector distance over tenant candidates, not an unfiltered global ANN lookup. HNSW and larger-corpus tuning require measurements and an authorization-preserving query review.

Explicit attachments preserve separate predicates: paper, immutable version, or exact selected page/passage. A version alongside another attached paper does not suppress that paper. Private annotations are independently resolved through annotation RLS. Selected text becomes evidence only when it is an exact substring of stored extraction; a fabricated or unavailable selection fails safely.

Bounds: twelve attachments/sources, 24 returned evidence records, four chunks per paper, 20,000 text bytes before metadata fallback, 24,000 including fallback/notes, 6,000 query characters, a five-second SQL statement timeout and ten-second tool result deadline. Model input bounds can reject a context before generation. A passage spanning chunk boundaries may need a shorter selection. Poppler and PDF.js extraction can differ; no fuzzy match is called verified.

Abstracts and metadata retain null source-version/page fields and explicit evidence kinds. They never imply full-paper access. All evidence is revalidated before context, during generation, on history/snapshot reads, and on citation resolution. Raw run RLS also checks that stored evidence is still visible. Read [Supabase permissions guidance](https://supabase.com/docs/guides/ai/rag-with-permissions) for the underlying RLS/vector model. Hosted vector queries and larger-corpus benchmarks remain unverified.
