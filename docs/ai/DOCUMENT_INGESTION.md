# Document ingestion

Only scanner-accepted `READY` immutable source versions on active, writable projects can be queued. `POST /api/v1/ai/index` requires an explicit source ID and `consent:true`; SQL resolves source/project ownership and current write capability. `(sourceVersionId, extractionVersion, embeddingKey)` is unique. No uploaded, quarantined or rejected file is indexed.

`ai_processing_jobs` is a transactional outbox with QUEUED, RUNNING, READY, RETRYABLE, FAILED and CANCELLED states, three attempts and five-minute leases/backoff. Worker claims use `SKIP LOCKED`; lease attempts fence stale completions. A separate completion-ownership flag prevents duplicate completions from paying for embeddings twice. Claim reconciliation cancels revoked/archived work and fails exhausted attempts. A new embedding revision creates a separate explicit index job. Retry exhaustion requires operator investigation, rather than resetting the attempt budget.

`ops/extractor` separates an HMAC broker from a secret-free Poppler container on an internal network. The broker has no database or Storage key, downloads only a short-lived grant from the approved Atlas Storage host, and checks size and SHA-256. The parser has a read-only filesystem, non-root UID, no external network, dropped capabilities, bounded tmpfs, process limits, 30 CPU seconds/35 wall seconds and a 512 MiB parser address-space ceiling. Container memory is 640 MiB. No PDF parser executes in a web request. The web completion handler accepts bounded extracted text and dispatches embeddings, never PDF parsing.

Text remains page-specific, with exact UTF-16 offsets, ordinal, extraction configuration, chunk checksum and original document checksum. Default chunks are 1,600 characters with 200-character overlap. No whitespace rewriting alters quotes. Limits are 500 pages, 500,000 extracted characters, 512 chunks, 16 embedding inputs per batch and 150 seconds for the embedding operation. Extraction completion bodies are capped at 2.1 MB and authenticated before JSON processing.

Worker SQL functions are granted only to `atlas_ai_worker`, not `atlas_runtime` or browser roles. The worker connection rejects ownership, elevated role membership and membership in `atlas_runtime`. Execution and commit recheck the initiating actor's current capability and source state. An absent worker leaves jobs pending. Image build and offline smoke verification do not imply a deployed worker, malware scanning or hosted ingestion.
