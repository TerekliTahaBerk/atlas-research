# AI security and privacy

Verified Supabase identity and transaction-local actor context gate every AI request. The non-owner web role keeps existing `atlas_runtime` restrictions; browser roles have no table/function access. Composite keys bind conversations/runs/usage/chunks/citations/jobs to their parents. Private conversations are creator-only, project access remains mandatory, and private annotations retain author ACLs. Retrieval is scoped in SQL before ranking; evidence is rechecked during generation, history loading and citation resolution. Run RLS independently rejects stale evidence.

The extraction SQL role is separate and has only narrow worker functions, no table access or privileged membership. The network-isolated parser gets neither credentials nor database connectivity. HMAC signing covers extraction action, timestamp and bounded body; lease attempts and completion ownership fence replay. A leaked broker key is still an incident requiring rotation and worker suspension.

Documents, metadata, user notes and conversation history are untrusted data. System instructions remain server-owned. Models get no database tool, secrets, Storage grant, actor email or hidden authorization prompt from clients. Tool names/schemas are fixed. Prompt injection cannot expand retrieval scope or execute a side effect through the current registry. Semantic resistance of an actual model still needs evaluation.

The user approves external processing in the live UI. Only the current prompt, bounded completed history, relevant authorized passages and minimal source identifiers/titles are sent to the configured generation provider; indexing sends accepted extracted text to the configured embedding provider. Workspace files are not sent wholesale. OpenAI Responses uses `store:false`; that flag alone does not establish zero provider retention. Anthropic/Google retention, region and account data-use settings must be reviewed before confidential research activation. Atlas implements no training reuse or consent to such reuse.

Logs contain normalized categories and request IDs only. No prompts, source text, auth tokens, provider errors, keys or signed URLs are logged by these services. Responses are private/no-store. Conversation deletion/retention is documented separately; immutable Library provenance is retained under its existing lifecycle. Hosted migration-history exposure, recovery verification and undeployed scanner/extractor are activation blockers, not reasons to claim Free-plan PostgreSQL is unavailable.

Hardening keeps `ai_evidence_visible` and `ai_references_visible` SECURITY INVOKER with fixed search paths and no browser EXECUTE. Canonical paper/version/page/start/text/hash identities, accepted source state, metadata kind and private annotation visibility are checked in one SQL statement under caller RLS. Delta updates and minimal state reads share a transaction; no final citation event is emitted without a freshly authorized completed snapshot. Run policies also check bounded transitive historical context, so a follow-up cannot outlive access to passages used in prior answers. Context snapshots are erased by conversation deletion/retention. Permission changes are checked before every delivered batch and during idle periods, without caching authorization. Already delivered browser content cannot be retracted.

The final review found and fixed a resolver boundary error: JavaScript `slice` truncates an excessive end offset, which could incorrectly accept an overlong citation range. Resolution now checks both endpoints explicitly. Location verification continues to carry `claimSupport: not-evaluated`; neither deterministic fixtures nor exact quotes establish scientific truth. [Performance evidence](STREAMING_PERFORMANCE.md) and the read-only [activation audit](../../ops/sql/phase-03-verification.sql) cover the revised boundary.
